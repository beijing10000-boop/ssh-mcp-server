# 运维控制台 UI 与交互规范

适用于 AI Ops Platform、SSH MCP Server、日志分析平台三个控制台。三者独立部署、独立登录、独立权限，但应当看起来、用起来是同一个产品。本文件在三个仓库中保持一致。

## 1. 共享设计系统 ui-kit

- `ui-kit.css` 与 `ui-kit.js`（AI Ops Platform 在 `web/assets/`，另两个在 `web/`）三个仓库**逐字节相同**，文件头写明版本（`ui-kit x.y.z`）。
- 修改流程：在任一仓库修改 → 在该仓库根目录运行 `python scripts/sync_ui_kit.py ../另两个仓库` → 三个仓库同时提交。`tests/test_ui_kit.py` 用 `ui-kit.sha256` 清单核对文件与版本号，未同步就会失败。
- 版本号：只改样式细节升修订号；新增组件或 API 升次版本号；删除或改变已有 API 升主版本号，并在三个仓库的 CHANGELOG 中注明。
- ui-kit 只放三处都用得到的令牌、外壳布局、通用组件和交互原语；单个控制台的页面样式留在各自的 `app.css`。
- 静态资源 URL 带版本参数（`?v=`），改动 JS/CSS 的发布要更新它，避免浏览器沿用旧缓存。

## 2. 布局与导航

- 左侧固定侧栏：品牌（图标 + 名称 + 副标题）、按“工作台 / 接入或配置 / 治理”分组的导航、底部版本与当前用户。窄屏收为抽屉。
- 内容区顶部：面包屑（`产品名 / 分组`）、页面标题、右上角“刷新”与“主题切换”。
- 每页先给出结论性信息（状态、计数、待处理事项），再给明细表格；低频配置放在“系统配置”的分页签里，不占主导航。

## 3. 视觉令牌

- 颜色只用令牌：`--text / --text-2 / --text-3`（三级文字）、`--accent`（链接与强调）、`--accent-fill`（主按钮、当前导航的底色）、`--green / --orange / --red / --indigo` 及其 `-soft` 底色、`--line`、`--surface`。图表配色、阴影、局部 SVG 可以例外。
- 对比度：正文与辅助文字在卡片底色上 ≥ 4.5:1；`--accent-fill` 与 `--on-accent` ≥ 4.5:1（浅色、深色主题都要满足）。
- 键盘焦点统一用 `--focus` 实线描边（`:focus-visible`），任何组件的阴影都不能盖住它。
- 主题：浅色 / 深色，跟随系统直到用户手动切换；偏好按站点保存在浏览器（键 `ui-theme`），三个控制台域名不同，互不影响。

## 4. 交互原语（ui-kit.js）

| API | 用途 |
| --- | --- |
| `UIKit.escape(value)` | 插入 `innerHTML` 或属性的任何数据都要转义；只有控制台自己拼的标记可以不转义 |
| `UIKit.notify(text, {type})` | 操作反馈。`type` 为 `success`、`error`、`info`；错误停留 12 秒并立即朗读；对话框打开时显示在对话框之上 |
| `await UIKit.confirm({title, message, confirmText, danger})` | 二次确认，返回 `true/false`。`danger: true` 时红色按钮，默认焦点在“取消” |
| `UIKit.guardUnsaved(isDirty)` | 表单有未保存修改时，离开页面前提示；返回解除函数 |
| `UIKit.icon(name)` / `UIKit.hydrate(root)` | 统一图标 |

## 5. 交互规则

1. **必须二次确认**（`UIKit.confirm`，`danger: true`）：删除、撤销或停用授权/令牌、停用核心功能（如平台基础 Skill）、缩短数据保留期或降低容量上限、授予或撤销管理员、取消正在运行的任务、批量覆盖配置。确认文案写清**对象、范围和后果**，例如“将删除 30 天前的系统日志，约 12 个分区，不可恢复”。
2. **新建/编辑**在对话框中完成。保存成功：关闭对话框、刷新列表、`notify(..., {type: "success"})`；保存失败：对话框保持打开，在表单内显示原因，已填写的内容不丢。
3. **测试连接/验证配置**：按钮进入“验证中…”并禁用；结果（成功，或失败原因与建议）显示在表单内，toast 只做补充。
4. **配置表单**有未保存修改时离开页面要提示；保存按钮旁显示“未保存的修改”状态。
5. **防重复提交**：请求进行中，触发按钮禁用；批量与重试类操作尤其如此。
6. **后台任务**（诊断、批次、采集）：列表显示状态与进度（完成/总数），详情可看结果与每项失败原因；失败可重试的给出“重试”。
7. **状态展示**：
   - 加载中：骨架或 `spinner`，不留空白；
   - 空数据：说明为什么为空、下一步做什么（例如“尚未接入日志来源，去接入指南”）；
   - 出错：说明哪里出错、能否重试，不把整页替换成一行错误；
   - 无权限：明确写“需要管理员权限”，不静默跳转；
   - 会话过期：提示“登录已过期，请重新登录”后再跳转。
8. **可读的标识**：审计和列表里显示人名、主机名、来源名；哈希或内部 ID 只作辅助。
9. **文本安全**：日志原文、主机诊断输出、告警内容、模型输出都是不可信数据，一律转义；不要把它们作为 HTML 或 Markdown 链接渲染。

## 6. 可访问性

- 所有操作可用键盘完成；对话框打开时焦点在对话框内，Esc 关闭。
- 状态不只靠颜色区分，胶囊里写文字。
- 尊重 `prefers-reduced-motion`。
