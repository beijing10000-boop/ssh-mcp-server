# 第 3 批：交互优化

- `web/interactions.js`、`app.js`：诊断目标改为服务端搜索（名称/IP/Host ID/组名），每次显示 20 台，独立的显式清单最多 100 台。删除资产页隐式联动；点击资产的“批量诊断”会明确复制本次选择到清单。主机详情抽屉包含准备清单、最后测试失败原因、最近诊断、快捷诊断与编辑；准备状态可引导绑定、扫描独立核验或测试。
- 主机批量按钮展示可执行数量；新增上次测试/诊断时间和白名单排序。主机/历史/审计的筛选与页码写入 URL hash，刷新可恢复。全局指示器独立轮询运行数、SSH x/4 和待执行 x/200。
- 批次视图显示进度、成功/部分/失败/取消/排队计数及跳过原因，只重试失败项；单台任务直接进入详情。补充任务返回 error/stderr 的最近失败原因保存。
- 指纹新增逐行预检（匹配、不匹配、算法不同、找不到、重复和格式错误）；不匹配记审计。确认独立可信来源后可只保存匹配项，保存时再次校验候选、目标签名和版本。旧整体原子确认默认行为保留，matched_only=true 才逐行跳过。
- 页面内影响范围确认弹窗替换全部原生 confirm；轮询对诊断历史按任务 ID 协调节点，避免新记录使焦点按钮换目标。Zabbix 轮询保留输入，仅禁用执行按钮，完成后恢复。

## 验证、迁移与兼容性

130 pytest、61 浏览器检查通过，含 Chromium 1280/1440/1920、实际 MCP SDK 和隔离 Zabbix 联调；无 JS 异常或 HTTP 5xx。ruff 规则/格式、Python 编译、全部 JS 语法与 diff 检查通过。新增 test_interactions.py 覆盖组名搜索/排序注入拒绝/主机详情、预检不写公钥、目标变化拒绝、匹配项确认及安全审计、只重试失败和队列鉴权。test_reliability.py 补等待期间令牌撤销、取得名额后禁止 SSH。browser_smoke.py 补显式目标、URL 恢复、抽屉、批次重试、页面确认和逐行指纹确认；ui_server.py 仅在显式测试环境提供一次失败和候选公钥夹具。

数据库由 init_db 的 CREATE INDEX IF NOT EXISTS 增加 host_id/action/completed_at 索引；时间列在查询中聚合，无新列、无历史回填。新增管理端点延续飞书管理员与 CSRF；公钥绝不自动信任。旧 API 的严格公钥确认行为不变；新增 matched_only 和预检接口，URL 老入口兼容。

尚未验证：生产 SSH / Zabbix、千台实测与真实飞书移动端。手机布局将在 UI 批次处理；容器依赖 GitHub CI。本批浏览器候选公钥和“独立台账”均为隔离夹具，不代表允许生产复制 SSH 扫描指纹作为可信来源。
