# v0.10.2 · 跳板主机支持公网地址

> 发布于 2026-11-11，基线为 v0.10.1（`37712b6`）。

本版允许把跳板（proxy）登记为公网 IP，用于被管主机在内网、而控制端只能经公网跳板到达的场景（如云上通过公网运维机中转到 VPC 内网主机）。不新增 MCP 工具，工具参数不变，无数据库结构变化。

## 变更

- **跳板地址可为公网 IP（proxy）**：`store.private_ip` 新增 `allow_public` 选项，仅在显式开启时额外接受可路由的全局单播地址；登记跳板（`POST /api/v1/proxies`）与连接跳板时开启它。回环、链路本地、组播、未指定地址仍一律拒绝。
- **被管主机仍限内网**：主机地址（`POST /api/v1/hosts`、主机连接、Zabbix 同步、MCP 工具按地址解析）的校验不变，只接受内网地址，默认行为与 v0.10.1 完全一致。

## 升级

1. 备份数据卷中的 `ssh-mcp.sqlite3`、`master.key`、`admin.token`、`mcp.token`。
2. 拉取新代码后 `docker compose up -d --build --wait`，`/healthz` 返回 0.10.2。
3. 如需使用公网跳板：登记跳板时填其公网地址与主机公钥，被管主机仍填内网地址并指向该跳板；控制端须能访问跳板的 SSH 端口，且跳板账号允许端口转发。

客户端授权与令牌不变，不需要重新授权。

## 回滚

检出 v0.10.1（`37712b6`）后重建；无数据库变化。登记过的公网跳板在旧版加载后，连接会按旧校验拒绝其地址，按需先删除该跳板与其下主机的绑定。
