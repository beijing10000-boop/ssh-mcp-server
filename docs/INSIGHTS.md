# Linux 空间与 IP 连接分析（中文）

## 1. 哪个目录占用空间最大？

登录 Web → **只读诊断** → 选择 Linux 主机 → **目录空间排行**。

输入扫描目录，例如 `/data`、`/data/mysql`、`/var/log`，执行后按实际分配磁盘空间降序显示**直接子目录**，可以通过改变路径逐级深入。

- 固定使用 `du -B1 -x -d 1`，最多运行 8 秒，低 CPU 优先级，不在目标主机创建文件。
- `-x` 不跨越其他挂载文件系统。例如 `/` 为一个分区、`/data` 为另一个分区时，需要单独扫描 `/data`。
- 系统不会自动全盘递归扫描，也不提供任意 Shell 工具；权限受 SSH 用户限制。
- 如果超时、目录不存在或权限不足，结果标为**部分完成**，不能误当作全部目录排行。

相应 MCP 工具：`ssh_diagnose_directory_usage(host_id, root="/data")`。

## 2. 哪个远端 IP 的 TCP 连接数最多？

选择 **远端 IP 连接数排行**。服务从目标主机执行 `ss -H -tan`，只读统计当前可见的 TCP 远端对端，并按连接总数降序显示前 50 项，同时统计其中的 ESTABLISHED 数量。

- 数据代表**当前 TCP socket 数量**，不是每个 IP 的流量，更不代表访问历史。
- 不包括 UDP；不保证含 NAT 网关上转发的数据。不存在 `ss` 时返回能力缺失，不会假装有结果。
- 适合识别连接风暴、某个客户端占用大量连接、服务端连接积压等方向。
- 对于连接状态判断，建议同时使用基础的 `ssh_diagnose_sockets`。

相应 MCP 工具：`ssh_diagnose_peer_connections(host_id)`。

## 3. 哪个远端 IP 的交互流量最大？

选择 **远端 IP 流量采样**。服务使用目标服务器现有的 `ss -ti` TCP 内核字节计数，间隔约 3 秒采样两次；按**两次都存在的同一条 TCP 连接**计算 `bytes_sent` 和 `bytes_received` 的增量，然后按对端 IP 聚合排序。

- 输出：对端 IP、发送增量、接收增量、总增量、约 3 秒平均字节/秒。
- **这不是服务器所有流量**。UDP、短连接、转发/NAT 流量、历史时段数据不纳入完整统计。
- `ss -ti` 是否提供所需计数取决于 Linux 内核及 iproute2 版本；没有字节计数时将明确返回“无法采样”，不根据连接数推算流量。
- 没有后台持续采集，不安装 Agent，也没有历史 IP 流量数据库。
- 若要准确统计服务器所有来源 IP / 目的 IP 在过去 1 小时的流量，包括 UDP、短连接、交换/转发流量，需要事先部署 NetFlow/sFlow/IPFIX、eBPF、conntrack accounting 或其他**有权限的、持续运行的流量采集器**。SSH 临时查询不能还原过去没有记录的流量。

相应 MCP 工具：`ssh_diagnose_peer_traffic(host_id)`。

## 使用约束

- 以上三个增强动作当前仅在 **A · 标准免 Agent** 模式提供。
- **B · 强制命令网关**尚未扩展这些诊断协议，尝试调用会返回明确的中文提示，既有 B 模式命令不受影响。
- 所有工具仍然要求目标主机登记、SSH 私钥授权、经独立核验的主机公钥和服务身份认证。
- 不支持修改网络配置、抓取原始封包、删除文件、执行修复、指定任意 SSH Shell。
