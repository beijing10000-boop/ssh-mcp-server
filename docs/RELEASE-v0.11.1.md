# v0.11.1 · 重新生成客户端令牌，删除不再使用的客户端

> 基线为 v0.11.0（`7fe1e61`）。

不新增 MCP 工具，工具参数与返回结构不变，无数据库结构变化。改的是 Web「系统配置 → MCP 接入」和它的两个管理接口。

## 变更

- **重新生成令牌**：令牌只在创建时显示一次，库里只存哈希。此前忘了令牌只能撤销这个客户端、换一个名称再建（已撤销的客户端仍占着名称，也删不掉）。现在对未撤销的客户端点「重新生成令牌」即可：
  - 同一个客户端签发一个新令牌，名称、诊断动作与主机范围不变；
  - 旧令牌从下一次请求起失效；
  - 有效期从现在起重新计算（默认 90 天），所以已过期的客户端也可以这样续期；
  - 「最近使用」清空，新令牌第一次被使用后重新出现，可据此确认使用方已经换上新令牌。

  已撤销的客户端不能重新生成令牌。接口：`POST /api/v1/mcp/clients/{id}/rotate`，body 可选 `{"valid_days": 1–365}`；审计 `mcp_client_rotate`。
- **删除客户端**：已撤销或已过期的客户端可以「删除」，名称随之可以重新使用。仍然有效的客户端要先撤销（直接删除返回 409），避免误删正在使用的令牌。接口：`DELETE /api/v1/mcp/clients/{id}`；审计 `mcp_client_delete`，detail 保留客户端名称。
- 它提交过的诊断任务和审计记录都保留（按客户端 ID 标识）；被删除客户端仍在排队的后台任务，轮到执行时会被拒绝。

两个接口与其他写接口一样，需要飞书管理员会话与 `X-CSRF-Token`。

## 升级

1. 备份数据卷中的 `ssh-mcp.sqlite3`、`master.key`、`admin.token`、`mcp.token`。
2. 拉取新代码后 `docker compose up -d --build --wait`，`/healthz` 返回 0.11.1。

已有客户端的授权与令牌不变。控制台脚本有改动，浏览器按新的 `?v=` 重新加载。

## 回滚

检出 v0.11.0（`7fe1e61`）后重建；无数据库变化。重新生成过的令牌继续有效，已删除的客户端不会回来。
